# 1. 概念设计

状态：进行时

所属阶段：设计管理阶段

工作流程：概念设计工作流程

## 会话工作规范

1. 用户有明确构想时，按原意理解记录，禁止擅自新增确定性概念；每次工作只向指定文件写入指定内容。
2. 助手的联想与建议置于回复的独立模块，标注"未确定"身份；一轮中未被用户直接回应的条目，下一轮作废。
3. 用户构想不明确并询问建议时，按设计层次分类回复，每部分标明设计层次及可考虑的内容。
4. 用户明确指示前，仅对话回复，不进行磁盘操作。
5. 内容简洁、以事实为核心；不擅自指定文档结构（除非用户明确允许）。

## 记忆整理

### 项目背景

- 个人项目：深度融合智能体技术，持续运行的新闻事件感知分析与投资建议生成系统。
- 本项目为重启版（前次尝试结果不理想）；设计顺序问题暂不关心。
- 近期重心：用户叙述，抽取前次有价值的设计，短期内快速搭建概念框架。

### 工作方式

- 本流程在设计管理阶段内，逐步明确系统功能、定位、运行逻辑与开发方式，产出 `docs/概念设计.docx`。
- 每轮作为有限范围的工作切片，开展概念扩展、验证与成果写入；落盘仍由用户明确指示触发。
- 本流程结束时总结成果与需调整部分，再由专门工作切片返回上层工作阶段；当前流程尚未结束。

- 用户主导叙述，助手记录并按规范 2 给出建议模块。
- 落盘由用户明确指示触发，可累积多轮后一次性落盘。

### 文档机制

- `docs/agents/` 文件名：`序号.标题-进行时/已完成`，序号自 1 起。
- 工作流程完成后：对应 agents 文档标记"已完成"，AGENTS.md 移除对应条目；AGENTS.md 保持简洁。

### 当前进度与下一步

- 已落盘：项目说明、文档目录规范、本工作记忆及 `docs/概念设计.docx`。概念设计已有项目整体介绍、业务与功能、项目定位与开发策略三章。
- 已明确：优先服务个人设备与个人投资；后期分发以稳定性和可用性得到验证为前提。分发包包含完整框架和选择性的个人资产示例，绝不包含运行时数据；当前仓库用于开发测试，线上分发另设仓库。
- 开发组织：设计管理、框架实施、测试与试运行、运行维护与分发四阶段交叉推进。阶段明确工作层级，工作流程组织内容与产出，工作切片限制单次增量；流程结束后总结并通过专门切片返回上层调整。
- 项目分工：当前为“AI辅助投资系统开发项目”；正式使用时另启“AI投资辅助系统运行项目”。运行 Agent 负责运行，开发 Agent 接收反馈、检查运行工作流并优化迭代。
- 尚待展开：用户资产初始建立的具体过程；运行后记录的经验如何进入用户资产。远程控制与通知仍为后续扩展方向。
- 下一步：继续由用户叙述概念，每轮限定扩展范围，核对概念关系后按明确指示落盘；具体后续主题与本流程结束时机由用户确定。
